// Symbols banned inside src/GitLab.Client only. Wired up by GitLab.Client.csproj as an
// <AdditionalFiles> item and deliberately NOT promoted to a repo-level Directory.Build.props: the
// GitLabJsonContextRegistrationTests guard legitimately calls JsonSerializerContext.GetTypeInfo(Type)
// and has to keep being able to.
//
// Every entry below resolves JSON metadata by System.Type at RUN TIME. They compile with zero
// IL2xxx/IL3xxx under EnableTrimAnalyzer/EnableAotAnalyzer - those analyzers assume the
// JsonSerializerContext supplies the metadata - yet they throw InvalidOperationException at run time
// when the type was never registered with [JsonSerializable]. That is the one way a forgotten
// registration can actually ship. Every call site in this library must instead pass a strongly typed
// JsonTypeInfo<T> (GitLabJsonContext.Default.<Type>), which turns a forgotten registration into a
// CS1061 compile error on the exact line.
//
// File format, verified against Microsoft.CodeAnalysis.BannedApiAnalyzers 5.6.0:
//   - One documentation-comment ID per line, optionally followed by ';' and a message.
//   - The comment marker is '//', NOT '#'. Blank lines are skipped, but a '#' line is parsed as a
//     declaration ID: it resolves to nothing and is silently dropped, and two identical ones fail
//     the build with RS0031 ("symbol '' is banned multiple times"). Do not use '#' here.
//   - An entry that fails to resolve is silently ignored, degrading the guard to a no-op with no
//     signal at all. Re-run the RS0030 probe described in CLAUDE.md after any major
//     System.Text.Json version bump.
//   - The file name must start with "BannedSymbols." and end with ".txt" or the analyzer ignores it.
//
// RS0030 is a warning by default and is only a build break here because src/Directory.Build.props
// inherits TreatWarningsAsErrors=true from the repo root.
